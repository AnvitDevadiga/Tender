The workflow

Five moves from issue to evidence.

Every step is a checkpoint. The agent can move fast; the benchmark still asks it to leave a trail.

01 / FIND

Issue

Pin the repository, revision, and task so the starting line is reproducible.

02 / MAP

Retrieve

Search the unfamiliar codebase and record what the agent looked at.

03 / MAKE

Patch

Generate a focused change inside an isolated workspace.

04 / PROVE

Test

Run tests, lint, and type checks. Capture output, not vibes.

05 / LEARN

Explain

Grade the result, classify failure, and decide whether to retry.

Field notes

Trust is a feature.

Tender is built to make autonomous software engineering inspectable enough to compare, debug, and improve.

What does “passed” mean?

A run passes only when the configured grader accepts the patch and the verification commands complete successfully.

Why keep an audit timeline?

It ties retrieval, tool calls, retries, tests, and failure categories to the final result instead of hiding the journey.

What makes a benchmark reproducible?

Each task pins a repository revision, issue statement, agent configuration, and output artifact. No invented metrics.

Built by Anvit.

Tender is a local-first evaluation bench for people who want coding agents to earn trust with evidence.
