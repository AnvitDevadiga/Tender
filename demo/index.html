What the project does

A coding experiment with a paper trail.

Think of it like a workshop: the agent gets a pinned task and a copy of the code, proposes a change, and tests it. ForgeBench stores the steps so a person can inspect the result instead of trusting a score with no explanation.

What is included today

Working pieces and honest gaps.

Built

Python and FastAPI prototype, SQLite run records, pinned benchmark tasks, bounded retrieval, patch-and-test workflow, isolated Docker execution, local worker, and a run explorer.

Optional model key

Offline checks need no API key. Real model-generated patches need a provider key; Groq is one optional adapter and may have usage limits.

Still in progress

Larger independent task coverage, LangGraph/MCP comparisons, PostgreSQL and migrations, public authentication and quotas, and a public execution backend.

Roadmap

From local prototype to a measured system.

Current
Expand the task set

Grow beyond three synthetic tasks, then repeat pinned trials before reporting general solve or retry performance.

Next
Advance workflow architecture

Compare orchestration and retrieval choices before adding durable checkpoints or more infrastructure.

Later
Consider public execution

Only after identity, quotas, a hardened sandbox, and an operational backend are in place.
