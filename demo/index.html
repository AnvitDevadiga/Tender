ForgeBench is a prototype workshop for asking a coding AI to fix a software task, run tests, and keep a record of what happened.

Live demo status: This page is a free, read-only portfolio demo. Running code tasks is currently a local feature and is not exposed as a public service. No benchmark scores are shown because no verified agent benchmark has been recorded yet.
What the project does

A coding experiment with a paper trail.

Think of it like a workshop: the agent gets a pinned task and a copy of the code, proposes a change, and tests it. ForgeBench stores the steps so a person can inspect the result instead of trusting a score with no explanation.

PrototypeGive it a task

Use a local issue or benchmark task tied to a specific repository version.

PrototypeTry a fix

Search relevant files, ask a configured model for a patch, and retry within a limit.

PrototypeKeep the evidence

Record run events, test outcomes, artifacts, and available token or cost data.

What is included today

Working pieces and honest gaps.

Built

Python and FastAPI prototype, SQLite run records, pinned benchmark tasks, bounded retrieval, patch-and-test workflow, Docker command runner, and a local run explorer.

Optional model key

Offline checks need no API key. Real model-generated patches need a provider key; Groq is one optional adapter and may have usage limits.

Still in progress

Human approval, LangGraph, MCP tools, PostgreSQL, public authentication and quotas, a separate worker, and measured benchmark results.

Roadmap

From local prototype to a measured system.

Current
Make local runs dependable

Harden task isolation, run recovery, traces, and reproducible benchmark evidence.

Next
Add safe human control

Build approval records and a durable worker path before enabling external writes or broader execution.

Later
Measure and publish

Run pinned tasks repeatedly, report real success and regression rates, then consider a public curated demo.
